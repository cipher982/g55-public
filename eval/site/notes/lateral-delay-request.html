What was asked

comma's driving policy takes an input for how much steering delay it should compensate (the lateral delay request). The truck's camera adapter feeds it 0.275 s. Does the policy's steering respond to that input in the closed-loop push bench, and by how much?

What was done

The closed-loop push bench (simulated vehicle) on 30 validation windows from 6 recorded drives of one truck and one driver, with the adapter's lateral request set to 0.275 s (the current value), 0.375, 0.475 and 0.775 s. Each pushed episode is a yaw push of 1.0 m or 1.5 m to each side. The result table uses the 25 windows at 10 m/s and over, which is 100 pushed episodes (50 per push size). The 5 slower windows are left out because at low speed the push is a lane-sized swing that no setting settles, which would dominate the means. The peak displacement is taken within the push, signed by push side, and every episode is paired with the same window at 0.275 s (the start state was checked to be identical). Intervals are 95% over windows.

Result

The action responds in every episode: the displacement peak within the push is smaller in 50 of 50 episodes at every larger request, for both push sizes. Each extra 0.1 s of request takes about 3 cm (1.0 m push) to 7 cm (1.5 m push) off the displacement during the push and about 3 cm off the overshoot. By 5.6 s there is no difference. The cost is on the unpushed episodes: steering activity rises with the request (all 30 windows: 0.057 at 0.275 s, then +0.003, +0.006 and +0.019), and at 0.375 s it is higher in 22 of 30 windows.

Correction of the first reading. The first reading of this run called 0.375 s a "matched" value with a larger gain (a peak about 0.27 m smaller). That was wrong. The larger number came from taking the peak over the whole episode instead of within the push, and from the slow windows, where episodes keep swinging. With the peak taken within the push and the slow windows removed, the gain is the 3 to 7 cm per 0.1 s above. Two outside model reviews caught this.

What it does not show

  • A better setting. The effect grows steadily with the request and has no best value, so this is sensitivity, not a match to anything. The bench's lateral controller already compensates the simulated vehicle's excess lag with a predictor built from the same numbers, so a larger request compensates the same lag a second time.
  • That a larger request costs nothing. Unpushed steering activity is higher, and 30 windows did not resolve how much that matters.
  • Anything under 10 m/s, which was excluded.
  • Anything on the road. The vehicle has no steering actuator, so the lateral action is not used there and nothing changes. An actuator's own delay would add to the number.
  • Whether the best request moves with the vehicle's delay: crossing the bench's actuator delay with the request was not run. Also not run: comma's longitudinal request.
  • Scale: one seed, a simulated vehicle, 25 windows in the table (6 drives of one truck and one driver), no training, nothing deployed.
