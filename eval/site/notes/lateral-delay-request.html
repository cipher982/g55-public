What was asked

comma's driving policy takes an input for how much steering delay it should compensate (the lateral delay request). The truck's camera adapter feeds it 0.275 s. Does the policy's steering respond to that input in the closed-loop push bench, and by how much?

What was done

The closed-loop push bench (simulated vehicle) on 30 validation windows from 6 recorded drives of one truck and one driver, with the adapter's lateral request set to 0.275 s (the current value), 0.375, 0.475 and 0.775 s. An addendum (below) adds three settings under the current value, 0.175, 0.075 and 0.0 s, so the series is seven settings. Each pushed episode is a yaw push of 1.0 m or 1.5 m to each side. The result table uses the 25 windows at 10 m/s and over, which is 100 pushed episodes (50 per push size). The 5 slower windows are left out because at low speed the push is a lane-sized swing that no setting settles, which would dominate the means. The peak displacement is taken within the push, signed by push side, and every episode is paired with the same window at 0.275 s (the start state was checked to be identical). Intervals are 95% over windows.

Result

The action responds in every episode: the displacement peak within the push is smaller in 50 of 50 episodes at every larger request, for both push sizes. Each extra 0.1 s of request takes about 3 cm (1.0 m push) to 7 cm (1.5 m push) off the displacement during the push and about 3 cm off the overshoot. By 5.6 s there is no difference. The first cost found was on the unpushed episodes: steering activity rises with the request (all 30 windows: 0.057 at 0.275 s, then +0.003, +0.006 and +0.019), and at 0.375 s it is higher in 22 of 30 windows. The addendum below finds a second cost, in turns.

Correction of the first reading. The first reading of this run called 0.375 s a "matched" value with a larger gain (a peak about 0.27 m smaller). That was wrong. The larger number came from taking the peak over the whole episode instead of within the push, and from the slow windows, where episodes keep swinging. With the peak taken within the push and the slow windows removed, the gain is the 3 to 7 cm per 0.1 s above. Two outside model reviews caught this.

What it does not show

  • A better setting. The effect grows steadily with the request, and across all seven settings none is better on everything (see the addendum), so this is sensitivity, not a match to anything. The bench's lateral controller already compensates the simulated vehicle's excess lag with a predictor built from the same numbers, so a larger request compensates the same lag a second time.
  • That a larger request costs nothing. Unpushed steering activity is higher, the truck sits further to the outside of turns (addendum), and 30 windows did not resolve how much the steering activity matters.
  • Anything under 10 m/s, which was excluded.
  • Anything on the road. The vehicle has no steering actuator, so the lateral action is not used there and nothing changes. An actuator's own delay would add to the number.
  • Whether the best request moves with the vehicle's delay: crossing the bench's actuator delay with the request was not run. Also not run: comma's longitudinal request.
  • Scale: one seed, a simulated vehicle, 25 windows in the table (6 drives of one truck and one driver), no training, nothing deployed.

Addendum, 2026-11-15: the cost in turns, and three settings below the current one

What was added. The unpushed runs were read for where the truck sits in turns, and the request was then run at 0.175, 0.075 and 0.0 s on the same bench, the same 30 windows and one seed. Together with the four settings above, the series is seven settings.

Turn steps are the steps of the 0.275 s unpushed run where the commanded lateral acceleration is 0.7 m/s² or more. 9 of the 30 windows have at least five of them (7 of the 9 are on roads with a centre line only). Every setting is scored on those same steps. "Outside" is the offset from the driver's recorded path on the outside of the commanded turn; the direction of the command was taken from the traces. Straight steps are those under 0.3 m/s². Push displacement is over the 100 pushed episodes on the 25 windows at 10 m/s and over, both push sizes pooled, each minus the same setting's unpushed run. Reading. The request moves two things in opposite directions across all seven settings. A larger request takes less displacement from a push and puts the truck further to the outside of the driver's path in turns, about 4 to 5 cm per 0.1 s. A smaller request does the reverse, and also sits a centimetre further from the path on straights. Below 0.275 s the push response is weaker per 0.1 s than above it, which fits an earlier open-loop study's finding that requests under about 0.3 s move the action little; the turn offset keeps about the same slope. No setting is better on everything: in turns the plain distance from the path is lowest at 0.175 s, by 1.3 cm, and no different at 0.0 s, because some windows move from the outside of the path to the inside of it.

What the addendum does not show. The reference is the driver's path, not the lane centre, and a driver may cut a turn, so "outside" is relative to this driver. Nine windows from three drives carry the turn result. The simulated vehicle and its controller are the bench's, and the truck has no steering actuator. One seed. No outside review was asked for: the addendum claims a trade, not an improvement.

Addendum, 2026-11-15: the request given separately to the policy's base part and to its learned correction

What was added. The request enters only the policy's base part; the learned correction reads the base part's outputs. In a measurement patch on a copy of the bench, the correction was computed from a second pass of the base part at one request, while the base action, the combine step and the carried state came from a pass at another. Two crossed runs were made on the same bench, the same 30 windows and one seed, scored with the same measures as the addendum above. Differences are against 0.275 s for both parts.

Reading. Raising the request to the base part alone takes more off a push than raising both (0.36 m against 0.21 m at 2 s) and puts the truck further outside in turns (0.20 m against 0.17 m). Raising it to the correction alone does the opposite on both, and the pushed episodes then do not come back by 4 s. So the push benefit and the turn cost both follow how the base part changes with the request, and the correction's own change with the request works against each of them. This fits an earlier finding that the correction largely replaces the base part (it falls by about 0.77 for each unit the base part rises): a correction computed for one base and added to another leaves the difference between the two in the action. Neither crossed setting is better than 0.275 s on both measures, and the ratio of push displacement gained to turn offset lost is about the same as for the uniform request. A crossed request is also an input the policy was never trained on.

What the addendum does not show. One seed, nine turn windows, the driver's path as the reference, the bench's simulated vehicle. Only two crossed settings were run. A grid was not, because both effects move together with the base part's request and nothing in these four rows points to a combination that escapes the trade. No outside review: the addendum claims where the effect sits, not an improvement.
