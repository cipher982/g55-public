What was asked

The turn-signal note found an input the truck had always fed as zeros. Are there other differences between how the truck feeds comma's driving model and how comma's own reference code feeds it, and does any of them change the plan?

What was done

  • A read-only comparison of every model input and processing step in the truck's perception code with the copy of comma's reference code and the notes kept on it. Nothing was run for this part.
  • One difference was measured. Two comments in the truck's code disagreed on which traffic side the fed setting stands for. Open loop on real camera frames of 17 drives of one truck and one driver, the run was repeated with the other setting, and the plan's sideways error at 4 s was compared. No training, no simulator, nothing deployed.

Result

Same as the reference, by reading: the pulse rule for the intent input, the image warp and focal lengths, which camera feeds which input, the 20 Hz pacing and in-graph history, the 0.3 s smoothing of the speed command and none on the steering command, and the reset on a non-finite output.

  • The truck feeds the right traffic-side setting. The other choice changes the 4 s plan error by +0.004 m, so the input barely matters to this model. The comment that said otherwise was corrected.
  • Apart from the intent input, no difference found changes the plan on recorded drives.

What it does not show

  • That the reference is the right behaviour. It is the comparison point, and the truck may differ from it on purpose.
  • Anything about the four unmeasured differences. They concern live timing and image handling, which recorded-drive evaluation cannot see because it does not replay the truck's live path.
  • That the comparison found everything. It was by reading, of the inputs and steps listed.
  • Anything in closed loop, or beyond 17 drives of one truck and one driver.
